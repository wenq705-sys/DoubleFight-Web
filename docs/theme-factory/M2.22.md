# M2.22 — AI Theme Factory / Premium Toy Diorama

Status: isolated prototype; DO NOT merge into the 1.0.10 review/release branch.

## Product contract
- The tile model itself communicates its 2048 tier. Do not overlay fixed numeric labels.
- Visual target: premium miniature toy diorama, with clean playable cells and rich peripheral scenery.
- First prototype: Night Market, one board and three visually distinct representative tile assets.
- Do not replace BattleBoardView or rewrite the existing rendering pipeline.
- Factory-first: manifest-driven geometry, reusable prop/material/animation/VFX/audio libraries.
- Performance-by-design: enforce triangle, material, draw-call, texture, audio and memory budgets at asset-build time; measure on target devices before finalizing thresholds.

## Prototype acceptance gates
1. Render contact sheet at actual phone tile size, including silhouette-only comparisons.
2. Export deterministic GLB assets from Blender bpy in headless mode.
3. Produce an asset manifest, validation report and explicit licensing/provenance record.
4. Load through a separate adapter with safe fallback, caching and resource ownership.
5. Check first load, repeated theme switch, all representative tiles, GPU disposal and device clarity.
6. Provide a standalone preview before wiring into the gameplay UI.
7. Review visuals and mobile performance before generating the full eleven-tier set.

## Workstream boundaries
- Creative Lab: art direction and three representative forms.
- Geometry/Material/Diorama Factory: Blender generators and export pipeline.
- Experience Factory: pooled runtime VFX, reusable SFX families and layered loopable BGM.
- Integration: isolated Three.js adapter; no mutation of production release configuration.
- Quality Gate: deterministic checks, screenshots, package-size and runtime telemetry.

## First implementation sequence
1. Inspect existing theme contracts, BattleBoardView and asset lifetime.
2. Implement manifest schema + validator with explicit performance budgets.
3. Build Night Market board prototype in Blender and render preview/contact sheet.
4. Export and test three assets in a standalone Three.js scene.
5. Integrate only after adapter and regression tests pass.
